# How to Add an Animated Contribution Snake to Your GitHub Profile

This guide walks through generating an animated snake that "eats" your GitHub contribution graph and embedding it in your profile README.

## Prerequisites

- A **profile repository**: a repo named exactly the same as your GitHub username (e.g. `robert-stevenson-1/robert-stevenson-1`). GitHub automatically shows the `README.md` from this repo on your profile page.
- That repo must be **public**.

## Step 1: Add the GitHub Action workflow

In your profile repo, create a new file at:

```
.github/workflows/snake.yml
```

With the following content:

```yaml
name: Generate Snake

on:
  schedule:
    - cron: "0 0 * * 0"   # weekly, midnight UTC every Sunday
  workflow_dispatch: {}
  push:
    branches:
      - main

jobs:
  generate:
    permissions:
      contents: write
    runs-on: ubuntu-latest
    steps:
      - name: Generate snake
        uses: Platane/snk@v3
        id: snake
        with:
          github_user_name: ${{ github.repository_owner }}
          outputs: |
            dist/github-snake.svg
            dist/github-snake-dark.svg?palette=github-dark

      - name: Push to output branch
        uses: crazy-max/ghaction-github-pages@v4
        with:
          target_branch: output
          build_dir: dist
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

This uses [Platane/snk](https://github.com/Platane/snk), the tool that actually renders the animated SVG from your contribution graph.

**Notes on the schedule:**
- `workflow_dispatch` lets you trigger it manually from the Actions tab.
- `push` to `main` regenerates it any time you commit.
- The `cron` line controls automatic regeneration — `"0 0 * * 0"` means weekly, every Sunday at midnight UTC. Change the last field (0–6, Sun–Sat) to pick a different day, or use `"0 0 * * *"` for daily.

## Step 2: Enable write permissions for Actions

Go to your repo's **Settings → Actions → General → Workflow permissions**, and select **"Read and write permissions"**. Save.

Without this, the workflow will run but fail silently when it tries to push the generated SVGs to a new branch.

## Step 3: Run the workflow once manually

Go to the **Actions** tab of your repo → select **"Generate Snake"** → click **"Run workflow"**.

Once it finishes (usually under a minute), it creates a new branch called `output` in your repo containing the generated SVG files.

## Step 4: Embed the snake in your README

Add this to your `README.md`, replacing `<your-username>` with your actual GitHub handle:

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="https://raw.githubusercontent.com/<your-username>/<your-username>/output/github-snake-dark.svg">
  <source media="(prefers-color-scheme: light)" srcset="https://raw.githubusercontent.com/<your-username>/<your-username>/output/github-snake.svg">
  <img alt="A snake eating through my GitHub contribution graph" src="https://raw.githubusercontent.com/<your-username>/<your-username>/output/github-snake.svg">
</picture>
```

The `<picture>` element automatically shows the dark-themed version on dark mode and the light version otherwise, with the `<img>` tag as a fallback for renderers that don't support `<picture>`.

Commit the change, and the snake should appear on your GitHub profile page within a minute or so (raw SVGs are cached briefly by GitHub's CDN).

## How it stays up to date

Once set up, the workflow re-runs automatically on the schedule you set, regenerating the SVGs from your latest contribution data and pushing them to the `output` branch — so the embedded snake keeps reflecting your current activity without any manual work.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Action fails on the push step | Workflow permissions aren't set to "Read and write" (Step 2) |
| Snake doesn't show up on profile | `output` branch wasn't created, or the README URLs don't match your username exactly |
| Image looks stale | GitHub's raw content CDN caches SVGs for a few minutes — wait and refresh |
| No `output` branch created | Check the Actions tab for a failed run and read the logs |
